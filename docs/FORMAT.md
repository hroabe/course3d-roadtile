# 道路タイルの形式（第1版）

この文書は道路タイルの形式の正本です。作る側（このリポジトリ）と読む側（大会コース3D スタジオ）は、この文書に従います。形式を変えるときは、先にこの文書を直します。

## フォルダの構成

```
<出力先>/<版の日付>/manifest.json            目録
<出力先>/<版の日付>/12/<x>/<y>.json.gz       マスのファイル（ズーム12、x・y はマスの番号）
```

- 版の日付は、元ファイル（Geofabrik の PBF）の更新時刻（UTC）の日付です。例：`2026-10-05`。
- 作業中は `<出力先>/.<版の日付>.partial` に書き、できあがってから名前を変えます。名前に `.partial` がついたフォルダは、途中で止まったものです。

## 共通の約束

| 項目 | 内容 |
| --- | --- |
| 座標 | 経度・緯度を 1e5 倍した整数（約1m）。OpenStreetMap の 1e7 倍の整数 `v` から `(v + 50) // 100`（小数点以下を切り捨てる割り算）で作る |
| マスの番号 | 一般的な地図タイル（Web メルカトル）のズーム12。マスの西端・北端の線の上の点は、そのマスに入る |
| 差分 | 「差分」と書いた並びは、1つ目がそのままの値、2つ目からは前の値との差 |
| 文字 | UTF-8 の JSON を gzip で圧縮したもの |
| 決まった結果 | 同じ元ファイルと同じ版の加工スクリプトからは、同じバイト列ができる |

## 道路網の考え方

- 対象にする道（`highway=*`）と、区間につける印は [PIPELINE.md](PIPELINE.md) の表のとおりです。
- **区切り点**：2本以上の道が共有するノード、道の両端、同じ道が2回通るノード。道は区切り点で区切り、区切り点から区切り点までを1つの**区間**にします。
- 区間は、道の ID と、その道の中での通し番号（0 から。道の向きの順）の組 `(way, seg)` で決まります。通し番号は、座標がないなどの理由で書かなかった区間も数えます。
- 区間は、通る（かもしれない）すべてのマスに入れます。「通るかもしれないマス」は、区間の各線分について両端の点が入るマスの範囲（縦横の範囲の四角）を合わせたものです。同じ区間は、どのマスでも中身が同じです。
- 座標のないノード（抜き出しの境目など）を含む区間は書きません。
- 区間の向きは道の向き（OpenStreetMap で点を並べた順）のままです。一方通行の向きは印で表します。

### マスのつなぎ合わせ方

1. 必要な範囲にかかるマスを読みます。
2. ノードは ID でまとめます（同じ ID は同じ座標です）。
3. 区間は `(way, seg)` でまとめます（同じ組は同じ中身です）。

これで、マスに分ける前の道路網と同じものに戻ります。

## 目録（manifest.json）

| 項目 | 内容 |
| --- | --- |
| `format` | `"course3d-roadtile"` |
| `formatVersion` | この形式の版。いまは `1` |
| `dataVersion` | 版の日付（フォルダ名と同じ） |
| `source` | 元ファイル：`file`（名前）、`bytes`（大きさ）、`sha256`、`timestamp`（PBF の更新時刻、ないときは null） |
| `generator` | 加工スクリプトの名前と版 |
| `zoom` | `12` |
| `coordScale` | `100000` |
| `bbox` | 範囲を絞って作ったときの範囲 `[西, 南, 東, 北]`。全体なら null |
| `roadKinds` | 道の種類の名前の並び。区間の `kind` はこの並びの番号 |
| `flags` | 区間の印の名前とビットの値 |
| `placeKinds` | 地名の種類の名前の並び。地名の `kind` はこの並びの番号（0.3.0 で末尾に `lake` を足した） |
| `railKinds` | 鉄道の線の種類の名前の並び。鉄道の線の `kind` はこの並びの番号（0.2.0 から） |
| `riverKinds` | 川の線の種類の名前の並び。川の線の `kind` はこの並びの番号（0.3.0 から） |
| `waterKinds` | 水面の種類の名前の並び。水面の `kind` はこの並びの番号（0.3.0 から） |
| `attribution` | `"© OpenStreetMap contributors"` |
| `license` | `"ODbL-1.0"` |
| `counts` | 合計：マスの数、バイト数、区間の数など |
| `tiles` | マスごとに `[x, y, バイト数, sha256, 区間の数, 地名の数]`。x、y の順に並べる |

## マスのファイル（`12/<x>/<y>.json.gz`）

```json
{
  "v": 1, "z": 12, "x": 3629, "y": 1619,
  "nodes": [ノード ID の差分…],
  "xy": [x, y, x, y, …],
  "edges": [[u, v, kind, flags, name, ref, way, seg, x, y, …], …],
  "names": ["", "国道1号", …],
  "places": [[kind, name, x, y], …],
  "rails": [[kind, flags, way, part, x, y, dx, dy, …], …],
  "rivers": [[kind, flags, way, part, x, y, dx, dy, …], …],
  "water": [[kind, flags, src, x, y, dx, dy, …], …]
}
```

| 項目 | 内容 |
| --- | --- |
| `nodes` | 区間の両端になるノードの ID。小さい順。差分 |
| `xy` | `nodes` と同じ順のノードの座標。経度・緯度の組を交互に並べた差分（前のノードとの差） |
| `edges` | 区間。`(way, seg)` の小さい順 |
| `names` | 文字の表。`names[0]` は空の文字 |
| `places` | 地名・駅・山頂・交差点名・施設。種類、座標、名前の順に並べる |
| `rails` | 鉄道の線（地図に描くだけ。道路網には入れない）。`(way, part)` の小さい順。0.2.0 から。ないマスは空として読む |
| `rivers` | 川の線（地図に描くだけ）。`(way, part)` の小さい順。0.3.0 から。ないマスは空として読む |
| `water` | 水面（湖・池・川の面など）の輪。マスの四角で切り取ったもの。0.3.0 から。ないマスは空として読む |

区間の行：

| 位置 | 内容 |
| --- | --- |
| 0 `u` | 始まりのノード（`nodes` の何番目か） |
| 1 `v` | 終わりのノード（同上）。輪になった道では `u` と同じことがある |
| 2 `kind` | 道の種類（`roadKinds` の番号） |
| 3 `flags` | 印（ビットの和）：橋 1、トンネル 2、一方通行（u→v）4、一方通行（v→u）8、通行禁止 16、自動車専用 32 |
| 4 `name` | 名前（`names` の番号。0 はなし） |
| 5 `ref` | 路線番号（同上） |
| 6 `way` | OpenStreetMap の道の ID。行の並びでの差分 |
| 7 `seg` | 道の中での通し番号 |
| 8〜 | 途中の点。`u` の座標から始めて、前の点との差を経度・緯度の順に並べる。前の点と同じ点は入れない |

地名の行は `[kind, name, x, y]` です。座標は前の行との差分です。地名は、その点が入るマス1枚にだけ入れます。面として描かれた施設（学校など）は、頂点の平均の位置にします。湖（`lake`）は、名前のある 10ha 以上の水面で、いちばん大きい外側の輪の重心の位置にします（0.3.0 から）。

鉄道の線の行：

| 位置 | 内容 |
| --- | --- |
| 0 `kind` | 種類（`railKinds` の番号）：rail、narrow_gauge、light_rail、subway、monorail、tram、funicular、aerialway |
| 1 `flags` | 印：橋 1、トンネル 2 |
| 2 `way` | OpenStreetMap の道の ID。行の並びでの差分 |
| 3 `part` | 道の中での通し番号。長い線は64頂点ずつ（境目の点は重ねる）に分け、座標のない点でも切る |
| 4〜5 | 最初の点の座標（そのままの値） |
| 6〜 | 2つ目からの点。前の点との差。前の点と同じ点は入れない（最後の点は残す） |

鉄道の線のひと続き（`part`）は、区間と同じく、通る（かもしれない）マスすべてに入れます。読むときは `(way, part)` で1つにまとめます。踏切などで道路と同じノードを使っていても、道路網の区切り点にはしません。

## 川の線と水面（0.3.0 から）

川の線の行は、鉄道の線の行と同じ並びです。

| 位置 | 内容 |
| --- | --- |
| 0 `kind` | 種類（`riverKinds` の番号）：river、canal、stream |
| 1 `flags` | 印：時期によって水がない（`intermittent=yes`）1 |
| 2 `way` | OpenStreetMap の道の ID。行の並びでの差分 |
| 3 `part` | 道の中での通し番号。分け方は鉄道の線と同じ（64頂点ずつ、境目の点は重ねる。座標のない点でも切る） |
| 4〜5 | 最初の点の座標（そのままの値） |
| 6〜 | 2つ目からの点。前の点との差。前の点と同じ点は入れない（最後の点は残す） |

川の線のひと続きは、鉄道の線と同じく、通る（かもしれない）マスすべてに入れます。読むときは `(way, part)` で1つにまとめます。

水面の行は、輪（閉じた線）1つです。

| 位置 | 内容 |
| --- | --- |
| 0 `kind` | 種類（`waterKinds` の番号）：lake、reservoir、pond、river、canal、water |
| 1 `flags` | 印：時期によって水がない 1 |
| 2 `src` | 元の OpenStreetMap の ID。道（閉じた道）は正の数、マルチポリゴンのリレーションは負の数（-ID）。差分にしない |
| 3〜4 | 最初の点の座標（そのままの値） |
| 5〜 | 2つ目からの点。前の点との差。最後の点から最初の点へ戻って閉じる（最初の点はくり返さない） |

- **向き**：外側の輪は反時計回り、内側の輪（島などの穴）は時計回りです（経度を右、緯度を上にしたとき）。塗るときは **nonzero（0 でない）規則** で、全部の輪を1つの形として塗ります。こうすると穴が抜け、重なった別の水面（川の面の中の池など）は塗られたままになります。
- **切り取り**：輪は、マスの四角（西・東の経線と、北・南の緯線）で切り取って、そのマスに入る部分だけを入れます。切り口はマスの境目の線に沿います。四角の中に頂点がない大きな湖でも、マスを覆う部分があれば入れます。マスごとの部分は重ならないので、読むときは全部のマスの行をそのまま集めて塗ります（まとめる必要はありません）。
- **間引き**：川の線と水面の輪は、Douglas–Peucker 法で、ずれが 1e7 倍の座標で 200（約2m）以内になるように点を間引いてから、分けたり切り取ったりします。道路と鉄道は間引きません。
- 並びは `src` の小さい順、同じ `src` の中では元の輪の順です。点が3つ未満になった輪と、面積が 0 の輪は入れません。

## 形式の版の上げ方

- 読む側が読めなくなる変更は `formatVersion` を上げ、この文書の版も上げます。
- `roadKinds`・`placeKinds`・`railKinds` の末尾に種類を足すのは、版を上げずにできます。読む側は、知らない種類を「その他」として扱います。
- 目録やマスに新しい項目（キー）を足すのも、版を上げずにできます。読む側は、知らない項目を無視し、ない項目は空として読みます（例：0.2.0 で足した `rails`・`railKinds`、0.3.0 で足した `rivers`・`water`・`riverKinds`・`waterKinds`）。
